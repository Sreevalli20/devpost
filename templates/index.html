About ProofPilot AI

ProofPilot AI is a professional AI evaluation tool that verifies AI-generated claims against user-supplied evidence.

Features

  • Claim Extraction: Automatically extracts checkable claims from AI-generated answers
  • Evidence Verification: Compares claims against trusted evidence sources (text and URLs)
  • Transparent Classification: Clear support, contradiction, and insufficient-evidence labels
  • Real-Time Metrics: Evidence support rate, contradiction rate, source coverage, and more
  • Exportable Reports: Download detailed evaluation reports in Markdown or JSON format
  • Evaluation History: Track past analyses with timestamps and results

How It Works

  1. Enter a question and AI-generated answer
  2. Provide evidence as text or URLs (or both)
  3. Click "Analyze Reliability" to extract and verify claims
  4. Review the verification results for each claim with explanations
  5. Export a detailed report if needed

Methodology

Claim Extraction: The system splits answers into sentences and filters out questions, hedging statements, and opinions to extract factual claims.

Evidence Verification: Claims are compared against provided evidence using heuristic text matching. The system looks for word overlap and semantic patterns to determine if evidence supports or contradicts a claim.

Verdict System:

  • Supported: Evidence contains information that aligns with the claim
  • Contradicted: Evidence contains negation or conflicting information about the claim
  • Insufficient Evidence: No relevant evidence found, or evidence is inadequate to verify the claim

Important: This is a baseline heuristic approach. Evidence similarity does not prove factual correctness. For production use, integrate with advanced NLI models or LLM APIs.

Metrics Definitions

  • Total Evaluations: Number of analyses performed
  • Total Claims: Total number of claims extracted across all evaluations
  • Supported Claims: Number of claims with supporting evidence
  • Contradicted Claims: Number of claims with contradicting evidence
  • Insufficient Evidence Claims: Number of claims without adequate evidence
  • Evidence Support Rate: Percentage of claims supported by evidence (supported claims / total claims × 100)
  • Contradiction Rate: Percentage of claims contradicted by evidence (contradicted claims / total claims × 100)
  • Source Coverage: Number of unique evidence sources referenced
  • Average Confidence: Average confidence score across all claims (0-100%)

Limitations

  • Heuristic Matching: Baseline verification uses text similarity patterns; it may miss nuanced relationships or produce false positives/negatives
  • URL Retrieval: URL fetching depends on network accessibility, website availability, and may be blocked by anti-bot measures
  • Evidence Quality: The system cannot verify the accuracy of the evidence itself—only whether claims align with provided sources
  • Context Understanding: The baseline approach does not deeply understand context, sarcasm, or implied meaning
  • Complex Claims: Multi-part claims or those requiring external knowledge may not be accurately evaluated

Privacy & Storage

  • Data Storage: This application uses SQLite for local storage. Data is stored in the application's database file.
  • Render Deployment: On Render's free tier, the filesystem is ephemeral. Data may be cleared when the service restarts or redeploys. This is a limitation of the free hosting tier, not a bug.
  • Data Retention: No data is sent to third-party AI services. All processing happens server-side.
  • User Responsibility: For persistent storage, consider upgrading to a paid deployment tier with persistent storage or integrating a cloud database service.

Security

  • SSRF Protection: URL fetching blocks localhost, private IP ranges, and internal addresses to prevent Server-Side Request Forgery attacks
  • Input Validation: All user inputs are validated and length-limited
  • No Code Execution: User-supplied content is never executed as code
  • Request Limits: Maximum request size is 10MB; maximum evidence text is 50,000 characters; maximum URLs per request is 10

Technology Stack

  • Frontend: Responsive HTML, CSS, and JavaScript
  • Backend: Python with Flask
  • Server: Gunicorn (production WSGI server)
  • Storage: SQLite database
  • Evaluation: Heuristic text matching (extensible for NLI models)
  • URL Fetching: httpx with BeautifulSoup for HTML parsing
  • Deployment: Render Web Service (free tier)
